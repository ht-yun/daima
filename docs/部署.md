# 部署

## 本机运行（开发）

双击 `启动码审.cmd`，打开 http://127.0.0.1:5173。
它同时拉起两个进程：前端 5173、API 8787。

## Docker（单端口）

```bash
docker compose up -d --build
# 访问 http://服务器IP:8080
```

容器里只跑一个进程：API 服务同时托管构建好的前端（`dist/`），所以对外只有一个 8080 端口，不需要 Nginx。

配置通过 `env_file: .env` 注入，`APP_HOST/APP_PORT` 在 compose 里固定为 `0.0.0.0:8080`。
日志写到容器内 `/app/logs`，compose 已把它挂到宿主机的 `./logs`。

**注意**：本机没有安装 Docker，所以镜像没有实际构建过。上面这套配置是按同一份代码路径写的，静态托管已经在本地验证（`GET /` 返回构建产物）。

## 访问口令（公网必读）

默认没有口令，谁能访问地址谁就能用。上公网前在 `.env` 里加一行：

```
APP_PASSWORD=换成一个你自己记住的口令
```

重启服务后，任何访问者都会先看到口令页。验证过的行为：

- 未带会话 Cookie 调 `/api/*` → `401 UNAUTHORIZED`
- 口令错误 → `401 BAD_PASSWORD`
- 口令正确 → 下发 HttpOnly Cookie（7 天），之后正常使用
- 本机与远端都受口令保护；此外 `/api/logs` 和 `POST /api/config` **只允许本机调用**，远端即使登录也会被 `403` 拒绝

桌面快捷方式不受影响：它走本机 `/api/ingest`，本机调用不需要口令。

## 云服务器

1. 装 Docker 与 compose 插件
2. 把整个项目目录（不含 node_modules、logs）传到服务器
3. 改 `.env` 里的 key
4. `docker compose up -d --build`
5. 可选：前置 Nginx 反代 + HTTPS

## 数据与日志

- 日志：`logs/app.log`，JSON Lines，单文件超过 5MB 轮转为 `app.log.1`
- 历史记录：存在浏览器 localStorage，不在服务器
- 上传的图片/音频：只在内存中中转，不落盘

## 健康检查

`GET /api/health` 返回 `{"ok":true}`，可直接给负载均衡或探针用。
