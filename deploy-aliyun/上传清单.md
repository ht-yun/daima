# 上传阿里云服务器 · 文件清单

本地根目录：`.\src-app`
服务器目录：`C:\codereview\src-app`
包体总量：约 28 MB（前端产物 5.7 MB + OCR 语言包 5 MB + 运行期依赖 22 MB）

> **2026-11-04 实测修正**：本文档第一版写的是「运行时不需要 node_modules」，这是**错的**。
> `server/index.mjs` 顶部确实只用 Node 内置模块，但它有两处**动态 import**：
> `formatJs()` 里的 `await import("prettier")`、`lintJs()` 里的 `await import("eslint")`。
> 按第一版清单部署后，服务器上 JS 格式化和 JS 规则检查全部报 `Cannot find package`。
> 必须上传这两个包的依赖树（约 22 MB / 95 个包），或改为在服务器执行 `npm install`。

| `server\lint_py.py` | — | Python 代码静态检查脚本（缺失只影响该功能） |

## 四、运行期依赖包怎么准备（prettier + eslint）

在本地临时目录只装这两个包，得到干净的依赖树：

```powershell
New-Item -ItemType Directory -Force -Path "D:\temp\rdeps" | Out-Null
cd "D:\temp\rdeps"
'{ "name":"runtime-deps","private":true,"dependencies":{ "prettier":"3.3.3","eslint":"8.57.1" } }' |
  Set-Content package.json -Encoding utf8
npm install --omit=dev --no-audit --no-fund

# 打包上传（1405 个文件 / 4.7 MB，比逐个 SFTP 传快得多）
Compress-Archive -Path ".\node_modules\*" -DestinationPath ".\nm.zip" -Force
```

服务器端解压：

```powershell
Expand-Archive "C:\codereview\nm.zip" -DestinationPath "C:\codereview\src-app\node_modules" -Force
Remove-Item "C:\codereview\nm.zip" -Force
```

验收标准：`node_modules` 下有 95 个包目录，且这两个文件存在：

```powershell
Test-Path "C:\codereview\src-app\node_modules\prettier\package.json"
Test-Path "C:\codereview\src-app\node_modules\eslint\package.json"
```

改完依赖**必须** `pm2 restart codereview`，动态 import 有模块缓存，不重启不生效。

## 五、Python 运行时（影响 Python 格式化与规则检查）

`/api/format` 和 `/api/lint` 的 Python 分支依赖服务器上有 Python 3 + black：

| 能力 | 依赖 | 缺失时的表现 |
|---|---|---|
| Python 规则检查 | `python.exe` 跑 `server\lint_py.py`（仅标准库 ast） | `engine: failed`，提示「没有可用的 Python 3 运行时」 |
| Python 格式化 | `python -m black` | 提示「服务器没有安装 black」 |

安装（服务器能出网时）：

```powershell
# 1. 装 Python（静默，写入系统 PATH）
Invoke-WebRequest "https://www.python.org/ftp/python/3.12.7/python-3.12.7-amd64.exe" -OutFile C:\codereview\pysetup.exe -UseBasicParsing
Start-Process C:\codereview\pysetup.exe -ArgumentList "/quiet","InstallAllUsers=1","PrependPath=1","Include_pip=1","Include_test=0" -Wait

# 2. 装 black（国内慢可加镜像）
& "C:\Program Files\Python312\python.exe" -m pip install black -i https://pypi.tuna.tsinghua.edu.cn/simple

# 3. 显式指定解释器（重要）
#    服务进程的 PATH 是启动时的快照，新装的 Python 不在里面，
#    用绝对路径最稳：在 .env 加一行
#    PYTHON_BIN=C:\Program Files\Python312\python.exe

# 4. 重启生效
pm2 restart codereview --update-env; pm2 save
```

> **不要**在 `.env` 里写死开发机的路径（例如 `C:\Users\Lenovo\...\python.exe`）。
> 这种路径随部署包上传到服务器后必然 ENOENT，而且报错信息会泄露本地目录结构。
> 代码已做容错：绝对路径会先做存在性校验，不存在则依次回退 `python` / `python3` / `py`，
> 全部失败时返回可读提示，不再抛堆栈。

## 六、一键打包（本地 PowerShell）

```powershell
cd ".\src-app"
Compress-Archive -Path "dist","server",".env","package.json","ecosystem.config.cjs" `
                 -DestinationPath ".\codereview-deploy.zip" -Force

# 核对包内清单（应只有 dist / server / .env / package.json / ecosystem.config.cjs）
Expand-Archive ".\codereview-deploy.zip" -DestinationPath "$env:TEMP\cr-check" -Force
Get-ChildItem "$env:TEMP\cr-check" -Recurse -File | Select-Object FullName, Length
```

上传后在服务器校验：

```powershell
cd "C:\codereview\src-app"
"server\index.mjs","dist\index.html",".env","ecosystem.config.cjs","dist\eng.traineddata" |
  ForEach-Object { "{0,-28} {1}" -f $_, (Test-Path $_) }
```

五行全部返回 `True` 才算传全。

## 七、上传注意

1. `.env` 含真实密钥，**用远程桌面复制或加密压缩包**传输，不要走过公开网盘分享链接。
2. 传输完成后立即在服务器上修改 `APP_USERS` 与 `APP_PORT`。
3. 若压缩包设置了密码，部署后记得删除服务器上的 zip 残留。
4. 上传目标目录用 `C:\codereview\src-app`，避免中文路径导致的编码异常。

## 八、v1.1 增量更新（只多传两个东西）

GitHub 仓库导入功能上线时，**不需要重传整包**，只需要：

| 序号 | 本地路径 | 服务器路径 | 说明 |
| --- | --- | --- | --- |
| 1 | `src-app\server\index.mjs` | `C:\codereview\src-app\server\index.mjs` | 新增 `/api/github/*` 两个接口 |
| 2 | `src-app\dist\` 整个目录 | `C:\codereview\src-app\dist\` | 前端新增「GitHub 仓库」页签 |

然后：

```powershell
cd C:\codereview\src-app
pm2 restart codereview --update-env
pm2 save
```

**不要传 `.env`**：本地是 `APP_PORT=8099`，服务器是 `8080`，覆盖会把服务打回本地配置。

`.env` 只按需追加两行（可选，见手册 14.3）：

```ini
GITHUB_TOKEN=ghp_xxxx
# GITHUB_PROXY=https://gh-proxy.com/
```

浏览器端如果还看到旧页面，按 `Ctrl+F5` 强刷一次（`index.html` 已设 `no-cache`，正常会自动更新）。
