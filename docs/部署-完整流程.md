## 二、上传清单

### ✅ 需要上传（共约 1.1 MB）

| 路径 | 大小 | 作用 | 必需 |
|---|---|---|---|
| `dist\` | 990 KB | 前端构建产物 | 是 |
| `server\index.mjs` | 37 KB | 后端服务（API + 静态托管） | 是 |
| `server\lint_py.py` | 3 KB | Python 语法检查脚本（可选功能） | 建议 |
| `.env` | 1 KB | 模型 Key、登录账号、端口配置 | 是 |
| `ecosystem.config.cjs` | 1 KB | pm2 配置 | 是 |
| `package.json` | 1 KB | 仅作参考，运行时不读取 | 可选 |

### ❌ 不要上传

| 路径 | 原因 |
|---|---|
| `node_modules\` | 平台相关，且有 200MB+；后端零依赖，完全不需要 |
| `src\` | 服务器不构建前端，传了也没用 |
| `tools\` | 本地开发/截图脚本 |
| `preview\` | 验证截图 |
| `eng.traineddata` | 5 MB，OCR 测试用，网页运行时不加载 |
| `app.ico`、`public\app.ico` | 打包时已进 dist 或仅本地快捷方式用 |
| `*.cmd`、`dev.cmd`、`build.cmd` | Windows 本地启动脚本，服务器用 pm2 |
| `PRD.md`、`项目完整源码.md` | 文档，不影响运行 |
| `Dockerfile`、`docker-compose.yml` | 本方案不用 Docker |

> 上传 `.env` 是**必需的**，因为没有它服务读不到模型 Key 和登录配置。
> 但这也意味着 `.env` 会离开你的电脑——见第五章风险 1。

## 三、服务器分步部署

### 步骤 1：远程登录

```
Win + R → mstsc → 你的服务器IP
账号：administrator（或你自己的管理员账号）
```

### 步骤 2：安装 Node.js

服务器浏览器打开（国内镜像）：

```
https://npmmirror.com/mirrors/node/v22.11.0/node-v22.11.0-x64.msi
```

双击安装，默认选项。安装完 **关闭所有 PowerShell 窗口再重开**，验证：

```powershell
node -v
npm -v
```

> 服务器上其实用不到 npm（后端零依赖），但装 Node 时自带，无所谓。

### 步骤 3：建目录并上传

```powershell
mkdir C:\codereview\src-app -Force
```

把第二章列出的文件复制进去，最终结构：

```
C:\codereview\src-app\
  ├─ dist\
  │    ├─ index.html
  │    └─ assets\
  ├─ server\
  │    ├─ index.mjs
  │    └─ lint_py.py
  ├─ .env
  ├─ ecosystem.config.cjs
  └─ package.json（可选）
```

### 步骤 4：先手动跑一次

```powershell
cd C:\codereview\src-app
node server\index.mjs
```

看到监听提示后，在服务器浏览器打开 `http://127.0.0.1:8080`。

- 能打开 → Ctrl+C 停掉，继续下一步
- 打不开 → 先解决，别往下走

> 端口默认就是 8080，`.env` 里没配 `APP_PORT` 时用默认值。要换端口就改 `ecosystem.config.cjs`。

### 步骤 5：pm2 常驻

```powershell
npm install -g pm2
cd C:\codereview\src-app
pm2 start ecosystem.config.cjs
pm2 status
```

`pm2 status` 里看到 `codereview` 为 `online` 即成功。

### 步骤 6：开机自启

```powershell
npm install -g pm2-windows-startup
pm2-startup install
pm2 save
```

三行顺序不能乱。以后**每次改了 ecosystem 配置或代码**，都要重新：

```powershell
pm2 restart codereview
pm2 save
```

验证：`Restart-Computer` 重启服务器，重连后执行 `pm2 status`，仍是 online 就说明自启生效。

### 步骤 7：放行端口（两处都要）

**Windows 防火墙**（管理员 PowerShell）：

```powershell
New-NetFirewallRule -DisplayName 'CodeReview 8080' -Direction Inbound -Protocol TCP -LocalPort 8080 -Action Allow
```

**阿里云安全组**：

| 授权策略 | 协议 | 端口 | 授权对象 |
|---|---|---|---|
| 允许 | TCP | 8080/8080 | 0.0.0.0/0（或你的 IP） |

### 步骤 8：公网验证

自己电脑浏览器打开：

```
http://你的服务器IP:8080
```

## 五、风险清单

### 风险 1：🔴 .env 密钥泄露（最高优先级）

`.env` 里有：

```
MODEL_API_KEY=sk-...       # DeepSeek
MM_API_KEY=sk-ws-...       # 千问
APP_USERS=admin:change-me  # 登录账号
```

**注意：已经验证过构建产物是干净的**——`dist/assets/*.js` 里搜不到这两把 Key（Vite 只注入 `VITE_` 前缀变量，本项目一个都没有）。Key 只会被后端读取。

但仍有四个泄露面：

1. **上传过程**：通过远程桌面剪贴板传 `.env`，如果剪贴板历史被记录，可能残留
2. **服务器磁盘**：任何能登服务器的人都能直接读 `.env`
3. **打包分发**：你现在的源码 zip 里是含 `.env` 的，转发前必须删
4. **对话/截图**：这两把 Key 已经在本会话中出现过，**建议立刻去官网轮换**

服务器上收紧权限：

```powershell
icacls C:\codereview\src-app\.env /inheritance:r /grant:r "$env:USERNAME:(R,W)"
```

### 风险 2：🔴 默认账号密码太弱

`APP_USERS=admin:change-me 一旦公网可达，任何人都能试。

**上线前必须改**，在 `.env` 里改成强密码：

```
APP_USERS=admin:change-me
```

改完 `pm2 restart codereview`。

### 风险 3：🟠 监听 0.0.0.0 等于全公网可达

`APP_HOST=0.0.0.0` 让服务监听所有网卡，配合安全组放行就是全网可访问。

- 只放行 **8080**，不要放行 8787、5173
- 8787 是旧 API 端口，5173 是 Vite 开发端口，都不该出现在服务器上
- 如果只是自己用，安全组授权对象填**你的固定 IP**，别用 `0.0.0.0/0`

### 风险 4：🟠 HTTP 明文传输

现在是 `http://`，登录密码在网络上是明文。公共 WiFi 下会被抓包。

方案 A（最简单）：用足够复杂的密码，且只从可信网络登录
方案 B：加 HTTPS。但不用 Nginx/IIS 的话，需要在 Node 里配证书，改动较大

### 风险 5：🟠 登录没有限流

`/api/login` 没有失败次数限制，可以被暴力破解。

缓解：强密码 + 安全组限制来源 IP。彻底解决要在后端加失败计数（目前没有）。

### 风险 6：🟡 远程桌面暴露

3389 端口如果对 `0.0.0.0/0` 开放，等于把服务器登录界面挂在公网上。

建议：安全组里 3389 只放行你的 IP；不用时关掉。

## 七、故障排查

| 现象 | 原因 | 解决 |
|---|---|---|
| 打开是白屏 | dist 路径不对 | 确认 `dist\index.html` 在 `src-app` 下 |
| 刷新 404 | 后端没做回退 | 本项目已内置回退，若 404 说明跑的不是 `server/index.mjs` |
| 页面能开，功能报错 | 只传了 dist，没传 server | 补传 `server\` 和 `.env` |
| 登录一直失败 | `.env` 没生效 | `pm2 restart codereview --update-env` |
| 端口被占用 | 8080 被别的程序占了 | `netstat -ano | findstr :8080`，或改 ecosystem 里的端口 |
| 外网打不开，本机正常 | 安全组没放行 | 见步骤 7 |
| pm2 重启后没了 | 没 `pm2 save` | 补执行 `pm2 save` |
